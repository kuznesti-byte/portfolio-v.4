# Иинжир — обучающая платформа с AI-преподавателем

> Кейс проекта: продукт, функционал, архитектура, технологии, интеграции, пользовательские сценарии.

---

## 1. О проекте

**Иинжир** — веб-платформа, которая учит профессии LLM-инженера через диалог с AI-преподавателем. Вместо пассивных видеокурсов — интерактивные занятия: преподаватель-персонаж ведёт по семишаговой структуре урока, разбирает ошибки в живом коде, подсказывает ступенями и никогда не даёт готовое решение.

**Проблема.** Курсы по ИИ либо перегружены теорией, либо сводятся к «повтори за видео». Ученик не получает обратной связи по своему коду, бросает на первой ошибке и не понимает, как складывать навыки в профессию.

**Решение.** Персональный AI-преподаватель, который:
- ведёт по методике из семи шагов (цель → модель → пример → практика → самостоятельное задание → проверка → фиксация);
- разбирает именно твой код и твою ошибку, а не абстрактный пример;
- подстраивает характер, тон и подробность под ученика;
- фиксирует навыки по уровням и строит из них учебный маршрут на 34 недели.

**Целевая аудитория** — люди, переходящие в ИИ-инженерию: от полного нуля («ни разу не писала код») до практиков, которые хотят системно закрыть RAG, агентов и продакшн-инфраструктуру.

## 2. Функционал

### 2.1. Авторизация и аккаунт (`auth.html`)

- Лендинг с анимированным фоном (морфящиеся пятна-ореолы с блужданием — повторение Figma-анимации).
- Вход по логину и паролю.
- Регистрация: имя, почта, пароль, кнопка «Сгенерировать» надёжный пароль.
- Сброс пароля: вводишь почту → приходит письмо со ссылкой → по ссылке форма «новый пароль дважды».
- Тёмная и светлая тема оформления (системная / ручной выбор), тема пробрасывается на все экраны.

### 2.2. Настройка обучения — шаг 01 (`setup.html`)

Персонализация траектории перед стартом:

| Настройка | Варианты |
|---|---|
| Уровень | Старт с нуля / Знаю основы / Уже пишу код |
| Нагрузка | 5 / 10 / 15 часов в неделю / свой ритм (с пояснением «≈3 часа в будни») |
| Преподаватель | **Фиг** (спокойный, без мата), **Луми** (логика и примеры), **Пикс** (юмор и энергия) |
| Формат | Текст / Голос |
| Стиль подачи | Коротко / Подробно |
| Ненормативная лексика | Вкл / Выкл (у Фига заблокирована всегда — он персонаж «без мата») |
| Тема пространства | Светлая / Тёмная / Системная |

Все выборы сохраняются и видны дальше на каждом экране; подсказка прямо говорит: «настройку можно изменить в любой момент».

### 2.3. Учебный план — шаг 02 (`plan.html`)

- Маршрут из 6 модулей (34 недели, 510 часов при ритме 15 ч/нед): Python-фундамент → HTTP и API → SQL и данные → LLM и evals → RAG и агенты → продакшн и портфолио.
- Клик по модулю меняет панель справа: спринты, задачи с часами, результат этапа и контрольная точка (гейты G1–G9).
- Чипы выбранных настроек («Старт с нуля», «15 часов в неделю», «Пикс · Текст · Подробно») — живые, читаются из настроек шага 01.
- Кнопки «Изменить план» (назад к настройкам) и «Принять план и начать» (первый урок).
- Ссылка на «Материалы для чтения».

### 2.4. Урок — шаг 03 (`index.html`)

Сердце платформы. Шесть уроков первой программы (списки и словари, условия, циклы, функции, JSON, ошибки и валидация), каждый по методике из семи шагов:

1. **Цель** — что построим и зачем.
2. **Модель** — минимальная теория.
3. **Пример** — разбор работающего кода.
4. **Практика** — тренажёр: код с намеренной ошибкой, запуск, чтение traceback, исправление.
5. **Самостоятельное задание** — вариация задачи с новыми данными.
6. **Проверка** — прогон по граничным тестам (обычный вход, пустой список, отсутствующее поле), обратная связь преподавателя.
7. **Фиксация** — ученик своими словами рассказывает решение; навык фиксируется на уровне 2.

Возможности экрана:

- **Тренажёр** — редактор кода с нумерацией строк, кнопки «Запустить», «Проверить задание», «Сбросить», терминал с построчным выводом (команда → traceback → код выхода).
- **Лестница подсказок** — 5 ступеней: от намёка до почти-готового фрагмента. Преподаватель никогда не выдаёт решение целиком — это правило платформы, зашитое в системный промпт.
- **Чат с преподавателем** — выбранный персонаж (аватар, имя, манера речи) отвечает с учётом контекста: текущий шаг, код ученика, хвост терминала, число показанных подсказок.
- **Голосовой формат** — диктовка ответов голосом и озвучка разборов преподавателя (см. интеграции).
- **Пауза** — занятие замораживается, состояние сохраняется, преподаватель «молчит» до возвращения.
- **Переключатель уроков** в шапке; после шестого урока — возврат к учебному плану.
- Тон «без шуток» — переключает обратную связь на сухую до конца занятия.

### 2.5. Материалы для чтения (`learn.html`)

Отдельная читалка-учебник без тренажёров:

- **13 глав в трёх частях** (~3,5 часа чтения): профессия и фундамент → модель и промпт → данные, RAG и агенты.
- **Интерактивный словарь**: 40+ терминов (от «токена» до «HNSW» и «Airflow») подчёркнуты в тексте; клик открывает боковую панель с объяснением, примером и полным указателем терминов.
- **Отметки «прочитано»** по главам с прогресс-баром; состояние сохраняется локально.
- Наглядные схемы-цепочки (конвейер RAG), блоки кода с подсветкой, чипы актуальных инструментов (LangChain, LangGraph, LlamaIndex, Qdrant, RAGAS, promptfoo, vLLM, Ollama, MCP и др.).
- Оценка времени чтения на каждую главу («16 мин чтения»).

## 3. AI-слой: движок преподавателя

Три модуля в `src/ai/`:

### 3.1. `prompts.js` — характер и правила

Собирает системный промпт из:
- **персоны** преподавателя (Фиг / Луми / Пикс — стиль речи, допустимость сленга и мата);
- **уровня** ученика (ноль → без жаргона; пишет код → коротко и по делу);
- **подробности** (1–3 предложения vs разбор с примером);
- **правил платформы**: не давать готовое решение, ссылаться на конкретную строку ученика, возвращать оффтоп к уроку, отвечать по-русски;
- **контекста урока**: название, навык, текущий шаг.

### 3.2. `analyzer.js` — разбор сообщений ученика

Правиловый препроцессор перед вызовом модели:
- классификация интента: приветствие / вопрос / вопрос с кодом / присланный код / «застрял» / паника («бесит, сдаюсь») / «дай готовое» / «понял» / оффтоп;
- извлечение кода из сообщения (fenced-блоки, inline, эвристика по токенам Python);
- определение эмоционального состояния;
- рекомендация действия: ответить / направить / отказать в готовом решении и дать подсказку / успокоить / вернуть к уроку — с поднятием уровня лестницы подсказок.

Тот же анализатор пост-фильтрует ответ модели: отсекает утечку готового решения и следит за соблюдением правил.

### 3.3. `tutor.js` — единый интерфейс ответов

Один движок, два режима:
- **api** — запрос на серверный эндпоинт `/api/tutor` с системным промптом, контекстным блоком (шаг, код, терминал, история диалога) и разбором сообщения;
- **mock** — локальный банк реплик для разработки и офлайн-демо; при недоступности API фронт молча откатывается на него, занятие не прерывается.

## 4. Архитектура

```
┌─────────────────────────────────────────────────────────┐
│  Браузер (SPA-экраны: auth / setup / plan / lesson /    │
│  learn). Статика, чистый JS, дизайн-токены из Figma.    │
└───────────────┬─────────────────────────────────────────┘
                │ REST (JSON)
┌───────────────▼─────────────────────────────────────────┐
│  Сервер — Node.js 20+ / Express                         │
│  ├── POST /api/tutor   диалог с преподавателем          │
│  ├── POST /api/auth/*  регистрация, вход, сброс пароля  │
│  ├── GET  /api/health  мониторинг                       │
│  ├── /api/progress     прогресс и навыки                │
│  ├── /api/stt          распознавание речи (прокси)      │
│  └── /api/tts          синтез речи (прокси)             │
└───┬─────────────┬──────────────┬────────────────────────┘
    │             │              │
┌───▼────┐  ┌─────▼──────┐  ┌────▼─────────────────────────┐
│ LLM     │  │ PostgreSQL │  │ Речевые сервисы              │
│ gateway │  │ (+pgvector)│  │ Yandex SpeechKit STT / TTS   │
│ OpenAI- │  │ users,     │  │ (потоковое распознавание,    │
│ совм.   │  │ progress,  │  │  живые голоса)               │
│         │  │ chats,     │  └──────────────────────────────┘
│         │  │ skills     │
└─────────┘  └────────────┘
```

Ключевые решения:

- **Ключи только на сервере.** Браузер никогда не видит LLM-ключ: фронт ходит на свой `/api/tutor`, сервер — на провайдера.
- **OpenAI-совместимый интерфейс** — провайдер LLM меняется конфигом (`LLM_BASE_URL`, `LLM_MODEL`), без правок кода.
- **Фолбэк-цепочка**: основной провайдер → резервный → локальный mock-банк. Занятие не ломается ни при каком сбое.
- **Настройки в localStorage** на прототипе синхронизируются с сервером при входе; дальше живут в базе.

## 5. Технологии

**Фронт**
- Чистый HTML/CSS/JS без фреймворка (экраны как отдельные страницы), Vite для разработки.
- Дизайн-токены из Figma: primary `#7450B5`, selected `#EAE2F5`, шрифт Onest, JetBrains Mono для кода.
- Собственные компоненты: тренажёр с терминалом, лестница подсказок, словарь-панель, анимированный фон (CSS-keyframes, блуждание и морфинг).

**Бэкенд**
- Node.js 20+, Express 4, ES-модули.
- `dotenv` для конфигурации, встроенный `fetch` для провайдеров.
- Эндпоинты тонкие: вся логика преподавателя переиспользует фронтовые модули (`prompts.js`, `analyzer.js`) через общий UMD-слой — один и тот же код работает в браузере и в Node.

**База данных**
- PostgreSQL 16: пользователи, настройки, прогресс, навыки, история чатов, сессии.
- pgvector — эмбеддинги учебных материалов для RAG-помощника.

**AI / ML**
- LLM через OpenAI-совместимый API: gpt-4o-mini как рабочая лошадка диалога, Gemini 2.5 Flash Native Audio — резерв и дешёвый голосовой режим, Qwen3-Omni — запасной сценарий.
- Распознавание речи: Yandex SpeechKit streaming (русский, потоковое, посекундная тарификация).
- Синтез речи: Yandex SpeechKit `livetts` (отдельный голос под каждого преподавателя).
- Качество: evals на golden dataset из 50+ сценариев диалога (promptfoo), трейсинг LangSmith.

**Инфраструктура**
- Docker и docker-compose: `web` (Express + статика), `db` (PostgreSQL), `worker` (фоновые задачи — дайджесты, переоценка навыков).
- Хостинг на VPS, домен с HTTPS (Caddy / Nginx, авто-сертификаты).
- CI через GitHub Actions: линт, проверка синтаксиса, прогон evals перед деплоем.

## 9. CJM: сценарий «Материалы для чтения»

Отдельная карта для читалки — у неё своя механика вовлечения.

| Этап | Действия ученика | Мысли и чувства | Боли | Решение в продукте |
|---|---|---|---|---|
| **1. Вход** | Замечает ссылку «Открыть материалы для чтения» на экране плана | «А, есть ещё и теория отдельно» | Страх очередной простыни текста | Сайдбар с главами и временем чтения: «16 мин — осилю» |
| **2. Ориентация** | Скроллит оглавление: 13 глав, три части | «Понятно, где я и что дальше» | Непонятно, с чего начать | Главы идут по маршруту программы, первая — «кто такой LLM-инженер» |
| **3. Чтение** | Читает главу, тыкает в подчёркнутые термины | «Токен… а, вот оно что» | Незнакомые слова ломают темп: приходится гуглить и терять нить | Словарь-панель поверх текста: объяснение + пример, не уходя со страницы |
| **4. Примеры** | Разбирает блоки кода и схемы-цепочки | «Ага, вот как это выглядит вживую» | Сухая теория без картинок | Подсвеченный код, схемы «вопрос → эмбеддинг → поиск → ответ», чипы инструментов |
| **5. Отметка** | Жмёт «Прочитано», видит рост прогресс-бара | «8% есть, двигаюсь» | Нет ощущения движения — бросает | Галочка в сайдбаре, процент, сохранение между визитами |
| **6. Возврат** | Возвращается на следующий день | «Где я остановилась?» | Потерянное место | Прогресс в localStorage, галочки на месте, продолжает со следующей главы |
| **7. Завершение** | Дочитывает последнюю главу, прогресс 100% | «Теперь понимаю, из чего собрана профессия» | — | Связка обратно в учебный план: теория подкрепляет уроки |

**Ключевые метрики сценария:** доля открывших хотя бы одну главу, среднее число открытий словаря на главу, % дочитавших до конца, возвраты на следующий день.

## 10. Метрики продукта

- **Активация:** % дошедших от регистрации до конца первого урока.
- **Удержание:** D7/D30, занятий в неделю на активного ученика.
- **Методика:** средняя ступень подсказки на ошибку (цель — падение от урока к уроку), % уроков, завершённых без истощения лестницы.
- **Навыки:** рост уровня по матрице навыков, прохождение гейтов G1–G9.
- **Голос:** доля выбравших голосовой формат, WER распознавания на русском, стоимость минуты голоса.
- **Экономика:** руб/урок по LLM+речь, доля кэш-хитов промптов.

## 11. Статус проекта

Рабочий прототип из четырёх экранов и читалки, AI-движок преподавателя с разбором интентов, сервер на Express с эндпоинтом диалога, подключённые провайдеры LLM и речи, PostgreSQL-схема, репозиторий на GitHub, домен и хостинг. Дальше по маршруту: второй модуль программы (HTTP и API), голосовой режим speech-to-speech и мобильная адаптация.
